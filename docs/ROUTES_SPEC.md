# ROUTES_SPEC.md

Guren has no separate API layer: controllers return Inertia pages (props typed to React) or redirects. JSON is used only where noted. Register routes in `routes/web.ts` (auth + private drive routes). Name every route and verify against `bunx guren graph`. The app is local and never internet-facing: it serves **no** public image route, and every shareable link points at the bucket's files domain (`docs/IMAGE_PIPELINE.md` §6).

Legend: 🌐 public · 🔒 requires login (inside the `auth` group) · **P** Inertia page · **R** redirect back (Inertia form) · **J** JSON.

---

## 1. Public (no login)

| Method | Path | Name | Returns |
|---|---|---|---|
| 🌐 GET | `/health` | *(none)* | **J** `{ ok, db, storage }` (200, else 503) |

Login routes are public too but belong to §2. That is the whole public surface: `/i`, `/t` and `/p` were removed (decision log 2026-11-18), because a link that resolves through this app dies whenever the machine is offline.

## 1a. Private image preview (🔒)

| Method | Path | Name | Returns |
|---|---|---|---|
| 🔒 GET/HEAD | `/preview/:publicId/:file` | `preview.show` | Image or thumbnail bytes of one pinned version (`IMAGE_PIPELINE.md` §4 to §5) |

- Exists so the local UI shows thumbnails and the lightbox with `STORAGE_DISK=local`, or before `PUBLIC_FILES_BASE_URL` is configured. With a files domain set, the server sends bucket URLs and the browser never calls this route.
- Never handed out as a link: a guest gets a redirect to `/login`. The response is `Cache-Control: private, max-age=31536000, immutable`.
- `{file}` is `{slug}.v{n}.{ext}` or `{slug}.v{n}.thumb.webp`; the slug is cosmetic and the version must exist.

## 3. Pages (all 🔒 **P**)

Common query params: `sort` = `name` \| `modified` \| `size` (default `name`), `order` = `asc` \| `desc`, `view` = `grid` \| `list` (also stored client-side).

| Path | Name | Props |
|---|---|---|
| `/` | `home` | redirect → `/files` |
| `/files` | `drive.index` | `{ folder, breadcrumbs, folders, images, moveTargets }` — `images` is **deferred** (announced in `deferredProps`, fetched by the client's follow-up partial reload behind the skeleton state); `moveTargets` is every active folder (task 2.4's "Move to…" picker) |
| `/files/:folderId` | `drive.folder` | same page and props as `drive.index`, resolved by folder id (shared action pair; Guren codegen keys contracts by route name, so the two paths carry separate names — decision log 2026-11-15). Unknown or trashed id → 404 |

## 4. Mutations (all 🔒)

### Folders
| Method | Path | Name | Body | Result |
|---|---|---|---|---|
| POST | `/folders` | `folders.store` | `{ name, parentId? }` | **R** |
| PATCH | `/folders/:id` | `folders.update` | `{ name?, parentId? }` | **R** |

Rules: name 1 to 255 chars, trimmed, no `/` or `\`. Create and move auto-suffix ` (1)` on a clash. Explicit rename onto an existing name → validation error. Moving into itself or a descendant → validation error `CYCLE` (400/422).

### Images
| Method | Path | Name | Body | Result |
|---|---|---|---|---|
| POST | `/uploads` | `uploads.store` | multipart: `file`, `format`, `quality?`, `maxDimension?`, `folderId?`, `name?` | **J** 201 `{ image, originalSize, storedSize, savedBytes, savedPercent }` |
| POST | `/images/:id/versions` | `images.replace` | multipart: `file`, `format`, `quality?`, `maxDimension?` | **J** 201 `{ image, originalSize, storedSize, savedBytes, savedPercent }` |
| POST | `/images/:id/versions/:version/restore` | `images.restoreVersion` | none | **R** (moves `current_version`) |
| PATCH | `/images/:id` | `images.update` | `{ name?, folderId?, starred? }` (task 2.2 ships `name`; `folderId` arrives with 2.4 Move, `starred` with 4.1 Star) | **R** |

- Upload errors (Guren's standard shapes): `413` too large, `415` unsupported type, `422` validation (bad option, unavailable format, pixel cap, AVIF on animated input), `503` storage unavailable. The UI shows `message` per file with a Retry.
- Renaming an image updates `name` and `slug`; it does **not** bump the version, so every permanent URL keeps resolving (lookups match `publicId`, the slug is cosmetic). A rename onto an existing sibling name is a `422` on `name`, shown inline. `:id` must be an active image — unknown or trashed → `404`.
- Replace requires the image to be active (not trashed).

### Bulk (body `{ imageIds: number[], folderIds: number[] }`, max 500 total)
| Method | Path | Name | Extra | Result |
|---|---|---|---|---|
| POST | `/items/move` | `items.move` | `targetFolderId: number \| null` (null = root) | **R** (atomic; whole request rejected on `CYCLE` or a name clash) |
| POST | `/items/star` | `items.star` | `starred: boolean` (images only) | **R** |
| POST | `/items/trash` | `items.trash` | | **R** |
| POST | `/items/restore` | `items.restore` | | **R** |
| POST | `/items/delete` | `items.delete` | | **R** permanent; only items already in trash; deletes all versions' objects, then rows |
| DELETE | `/trash` | `trash.empty` | | **R** permanent delete of everything in trash |

Permanent deletes: objects first, then rows. On storage failure keep rows and return an error flash.

Trash (tasks 4.2 and 6.3): `items.trash` sets `deleted_at` on the named items **and moves every affected version's objects under the `trash/` key prefix** — a bucket served directly by its files domain must stop answering the live key at once; a trashed folder hides its descendants and moves their objects too. `items.restore` clears `deleted_at`, moves the objects back to their live keys, puts the item at the root when its parent is missing or trashed, and suffixes a name clash ` (1)`. If the object move fails, the rows stay (trash) or return to the Trash (restore), so a retry can finish and nothing is left half-hidden. `items.delete` and `trash.empty` share one permanent-delete path: only items already in the Trash; a trashed folder takes its whole subtree (images and subfolders, trashed or not); every version's objects go before any row (both the live and `trash/` keys), images are deleted before folders so the foreign keys never block, and a storage failure keeps the rows for a retry.

`items.move` (task 2.4): one transaction moves every image and folder; items already in `targetFolderId` are no-ops and are not counted. A folder into itself or a descendant → `targetFolderId` `CYCLE`; an unknown/trashed item → `items`; a name clash with an active sibling in the destination (case-insensitive) → `targetFolderId`. No clash is auto-suffixed — a move is a relocation, not a create. The redirect lands on the source folder of the first moved item, so the browser never depends on `Referer`.

## 5. Middleware and cookies

- Private routes: session + CSRF (Guren `auth: {}`) + `auth` alias (`requireAuthenticated({ redirectTo: '/login' })`). This includes the preview route in §1a: its bytes are for the owner's browser only.
- `createApp` runs with `autoSession: false, autoCsrf: false`, and `app/Providers/SessionCsrfProvider.ts` mounts the same session/CSRF middleware for every path except `/health`, which is a bare monitor probe (the framework's CSRF middleware sets `XSRF-TOKEN` on every safe request and its session middleware re-issues the session cookie; `csrfOptions.exclude` cannot prevent either). `/login` and `/logout` are unaffected.
- The upload endpoints accept the CSRF token via the `X-XSRF-TOKEN` header (cookie `XSRF-TOKEN`).
- Rate limiting (task 5.2): login keeps its throttle; `POST /uploads` and `/images/:id/versions` a modest one. There is no public image route left to rate-limit.

## 6. Route-guard sweep

`tests/route-guard.test.ts` iterates every registered route that is not `GET`/`HEAD` and asserts an unauthenticated request is not 2xx. It also asserts the public allowlist in §1 is exactly the set of routes reachable without login.

The sweep sends its mutations as a **CSRF-primed guest**, not a bare request: a bare request is refused by the CSRF middleware on every route, so the assertion would hold even with no `auth` guard at all. With the token, the request reaches the route's own middleware and controller, and a 2xx means no guard stands between a stranger and the action.

The allowlist is now just `login` and `GET /health`: the preview route and every drive page are private, and no image route is public.
